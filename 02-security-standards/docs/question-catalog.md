## SEC01 - One-time passwords: HOTP

**Question:** Using HOTP as specified in RFC 4226 with HMAC-SHA-1, the shared secret equal to the ASCII string 12345678901234567890, and 6 digits, what is the HOTP value for counter value 5? Give all six digits.

**Answer:** `254676`

**Reasoning:** Computing HMAC-SHA-1 over the 8-byte big-endian counter 5, applying dynamic truncation (last 31 bits at the offset given by the low nibble of the last byte) and reducing mod 10^6 gives 254676, matching the RFC 4226 Appendix D test table (counts 0-9: 755224, 287082, 359152, 969429, 338314, 254676, 287922, ...).

**Designed shortcut:** Off-by-one in the counter (taking the value for count 6). (gives `287922`)

**Verification:** both (`verifiers.hotp_counter_5`)

**Sources:**
- RFC 4226: HOTP: An HMAC-Based One-Time Password Algorithm - Section 5.3 (dynamic truncation: 'Return the Last 31 bits of P'; 'D = Snum mod 10^Digit') and Appendix D (test values) <https://datatracker.ietf.org/doc/html/rfc4226>

## SEC02 - One-time passwords: TOTP

**Question:** Using TOTP as specified in RFC 6238 with HMAC-SHA-1, the shared secret equal to the ASCII string 12345678901234567890, T0 = 0, time step X = 30 seconds and 8 digits, what is the TOTP value at Unix time 1111111109? Give all eight digits, including any leading zero.

**Answer:** `07081804`

**Reasoning:** T = floor(1111111109/30) = 37037036. HOTP(secret, 37037036) with 8 digits is 07081804, as in the RFC 6238 Appendix B test vectors. The leading zero is part of the code.

**Designed shortcut:** Treating the code as a number and dropping the leading zero. (gives `7081804`)

**Verification:** both (`verifiers.totp_1111111109`)

**Sources:**
- RFC 6238: TOTP: Time-Based One-Time Password Algorithm - Sections 4.1-4.2 (X, T0, T = floor((Current Unix time - T0)/X)) and Appendix B (test vectors) <https://datatracker.ietf.org/doc/html/rfc6238>

## SEC03 - One-time passwords: time-step counter

## SEC04 - Password strength: entropy

**Question:** Password A is 12 characters chosen uniformly at random from the 94 printable ASCII characters. Password B is 6 words chosen uniformly at random from a 7776-word list (Diceware). How many more bits of entropy does A have than B? Give the difference in bits, rounded to 2 decimal places.

**Answer:** `1.11`

**Reasoning:** Entropy of A = 12 x log2(94) = 78.66 bits. Entropy of B = 6 x log2(7776) = 77.55 bits. Difference = 1.11 bits: the two are almost equally strong even though B is far easier to type.

**Designed shortcut:** Assuming a 12-character password is vastly stronger than 6 words, or comparing lengths instead of entropy. (gives `30.0`)

**Verification:** code (`verifiers.entropy_gap_bits`)

## SEC05 - Hashing: birthday bound

**Question:** A hash function outputs 64 bits uniformly at random. How many random inputs, in billions and rounded to 2 decimal places, must be hashed for the probability of at least one collision to reach 50%?

**Answer:** `5.06`

**Reasoning:** Solving 1 - exp(-n(n-1)/(2N)) = 0.5 with N = 2^64 gives n = 1.1774 x 2^32 = 5.06 x 10^9. The commonly quoted '2^32' is only the order of magnitude: it corresponds to about 39% probability.

**Designed shortcut:** Quoting 2^32 = 4.29 billion as the 50% point. (gives `4.29`)

**Verification:** code (`verifiers.birthday_50pct_billions`)

**Sources:**
- Menezes A, van Oorschot P, Vanstone S. Handbook of Applied Cryptography (1996) - Chapter 2 (probability background, birthday problem)

## SEC06 - Vulnerability scoring: CVSS v3.1 scope change

## SEC08 - Password hashing: Argon2 parameters

**Question:** RFC 9106 Section 4 gives a FIRST RECOMMENDED option for a uniformly safe Argon2id configuration with t = 1, p = 4 and m = 2^21 (memory given in KiB). How much memory does this option specify, in MiB? Give an integer.

**Answer:** `2048`

## SEC09 - HOTP: modulo bias of dynamic truncation

**Question:** In RFC 4226 the dynamic-truncation step yields a 31-bit integer Snum, uniformly distributed over 0 to 2^31 - 1, and the 6-digit code is Snum mod 10^6. How many of the 2^31 possible Snum values produce the code 000000? Give an integer.

**Answer:** `2148`

**Reasoning:** 2^31 = 2,147,483,648 = 2147 x 10^6 + 483,648. Codes 000000-483647 are produced 2148 times and the remaining codes 2147 times, so 000000 occurs 2148 times - a slight bias in the code distribution.

**Designed shortcut:** Assuming a perfectly uniform distribution (2147 values per code). (gives `2147`)

**Verification:** both (`verifiers.hotp_zero_code_count`)

**Sources:**
- RFC 4226: HOTP: An HMAC-Based One-Time Password Algorithm - Section 5.3 (dynamic truncation: 'Return the Last 31 bits of P'; 'D = Snum mod 10^Digit') and Appendix D (test values) <https://datatracker.ietf.org/doc/html/rfc4226>
